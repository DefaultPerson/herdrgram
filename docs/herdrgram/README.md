# herdrgram

Telegram ⇄ Claude Code через **herdr** (без tmux): ушёл от компа — продолжаешь ту же сессию в Telegram, вернулся — продолжаешь в herdr, пишешь с любой стороны.

Статус (2026-09-13): фаза исследования и планирования, кода нет.

- `docs/DECISION.md` — главный вывод: готовый мост уже существует (`alexei-led/ccgram`, herdr-бэкенд, MIT); рекомендация «adopt + маленький форк» вместо переписывания ccbot.
- `docs/PLAN-adopt-ccgram.md` — план внедрения ccgram с патчами (пробный прогон → форк → PR в апстрим).
- `docs/research/` — проверенные факты об API herdr 0.7.1, конспект сокет-API, обзор существующих проектов, gap-анализ ccgram.
- `docs/plan-b/` — задел на полную реализацию с нуля (на случай, если ccgram не подойдёт): карта переиспользования модулей ccbot. Дизайн/план с нуля не дописаны — воркфлоу остановлен после пивота на ccgram, его можно возобновить (см. docs/plan-b/README.md).

## Запуск (тестовый стенд, 2026-09-13)

- Форк: этот репо = `alexei-led/ccgram` v4.10.3 + патчи herdrgram (`git log upstream/main..main`). Remote `upstream` указывает на ccgram.
- Конфиг: `~/.ccgram/.env` (токен тестового бота `@your_bot`, `CCGRAM_MULTIPLEXER=herdr`, флаги патчей включены, `AUTOCLOSE_DONE_MINUTES=0`, `AUTOCLOSE_DEAD_MINUTES=2`).
- Хуки Claude Code: `uv run ccgram hook --install` уже выполнен (9 событий рядом с herdr-хуком; проверка `uv run ccgram doctor`; откат `uv run ccgram hook --uninstall`).
- Процесс: systemd user unit `~/.config/systemd/user/ccgram.service` (`ExecStart=.venv/bin/ccgram`, `WorkingDirectory=` этот репо, `Restart=on-failure`). Команды: `systemctl --user status|restart|stop ccgram`, логи `journalctl --user -u ccgram -f -o cat`. После правок кода: `systemctl --user restart ccgram`.
- Скрыть сессию от бота: `herdr tab rename <tab_id> __имя__`. Вернуть: `herdr tab rename <tab_id> имя`.

### Патчи поверх апстрима
- `CCGRAM_KILL_ON_TOPIC_CLOSE` — закрытие/удаление топика убивает панель herdr (в апстриме вручную запущенные сессии не убиваются никогда).
- `CCGRAM_DELETE_TOPIC_ON_AUTOCLOSE` — автозакрытие мёртвого топика удаляет его, а не закрывает.
- `/show` и кнопка тулбара `show` — фокус на панель сессии в herdr (`herdr agent focus`, fallback `tab focus`).
- `CCGRAM_ECHO_USER_MESSAGES=false` — не дублировать в Telegram то, что набрано в терминале.
- `CCGRAM_HERDR_NOTIFY_ON_INJECT` — тост herdr «Telegram → <сессия>» при доставке сообщения из Telegram.
- `CCGRAM_TOPIC_NAME_DECORATIONS=false` — в имени топика только чистое имя: ни эмодзи статуса, ни бейджей RC/YOLO, и смена состояния больше не переименовывает топик (переименование прилетает только когда меняется само имя, т.е. когда переименовали вкладку herdr).
- `CCGRAM_TOPIC_RANDOM_ICON` — каждому топику, который создаёт ccgram, случайная иконка из набора Telegram (`getForumTopicIconStickers`, 112 штук) и случайный цвет из шести разрешённых; в пределах чата иконки стараются не повторяться, а если чат не принимает кастомную иконку (приватный чат) — остаётся один цвет.
- `CCGRAM_MUX_RENAME_FROM_TELEGRAM=false` — переименование топика в Telegram не уходит в herdr (`tab rename` переименовал бы вкладку всем соседним панелям); имена текут только herdr → Telegram, локально ничего не запоминается — набранное в Telegram имя живёт до следующей смены метки вкладки.
- `CCGRAM_HERDR_TOPIC_LABEL=tab` — имя топика = метка вкладки herdr как есть (включая голый номер у неназванной вкладки), ` ▸ <панель>` дописывается только там, где в одной вкладке несколько агентов.
- `CCGRAM_TOPIC_ON_DEMAND` — новая сессия больше не создаёт топик сама: в General прилетает одно сообщение «🆕 Новая сессия: <имя> / 📁 <cwd> / 🤖 <провайдер>» с кнопками [🧵 Открыть топик] [🙈 Скрыть]. «Открыть» создаёт топик обычным путём (та же случайная иконка, то же имя, та же привязка, та же догрузка истории — см. следующий пункт). Предложение одно на окно, переживает рестарт бота, при смерти окна превращается в «⛔ Сессия завершена: <имя>» и забывается. «Скрыть» удаляет сообщение и запоминает окно навсегда (привязать всё ещё можно через `/sessions` и пикер `/new`). Повторное нажатие «Открыть» (или нажатие вторым человеком) второй топик не создаёт. Состояние — `~/.ccgram/topic_announcements.json`.
- `CCGRAM_TOPIC_BACKFILL_MESSAGES` (по умолчанию 0 = апстрим, ничего не догружается) — сколько последних сообщений транскрипта показать в только что привязанном топике. При `=10` каждый топик, который ccgram привязывает, открывается шапкой «⏮ В сессии N сообщений, пропущено M — ниже последние K» (или «⏮ Загружена вся история: N сообщений», если всё влезло; у молчащей сессии шапки нет вовсе), затем K сообщений по порядку в формате `/history` (👤 у реплик пользователя, тулколлы свёрнуты). Работает на всех путях первой привязки: автосоздание топика при обнаружении сессии, пересоздание топика через `/sync` после удаления, «Открыть топик» из предложения, выбор окна в пикере `/new`. Сознательно не работает там, где сессию возобновляют в топике, который уже показывал предыдущую (баннер мёртвого окна, `/resume`) — там история уже на экране и часть её продублировалась бы. Перед чтением транскрипт помечается доставленным до текущего конца, а догрузка ограничена этой же отметкой, поэтому живой поток продолжается ровно оттуда: ничего не дублируется и «Jump to live» не всплывает. Отправка идёт с обычным троттлингом, десять сообщений — примерно десять секунд.
- `CCGRAM_HERDR_REQUIRE_NATIVE_SESSION` — чинит две вкладки на одну новую сессию Claude: herdr сначала публикует запись без `agent_session` (ccgram делает для неё подменную identity из terminal_id), а через 2–3 с — настоящую; таргеты у них разные, поэтому апстрим успевал создать топик на подменную, а потом второй на настоящую, и первый умирал и автозакрывался. С флагом подменная запись становится `topic_eligible=False`: её не усыновляют и не анонсируют, но она остаётся в полном листинге, так что liveness и очистка её видят и ни один уже привязанный топик не считается мёртвым. Цена — новая сессия появляется на пару секунд позже.
- `CCGRAM_HERDR_NATIVE_STATUS_AUTHORITY` — статус панели решает сам herdr, а не соскоб экрана. Апстрим сначала парсит терминал и спрашивает бэкенд только если не нашёл ничего, поэтому любая строка, похожая на спиннер, перебивает того, кто реально знает состояние: Claude Code оставляет глиф спиннера на строке завершённого хода (`✻ Sautéed for 2m 26s · done 11:06 AM · 1 shell still running`), ccgram читал её как «работает», и топик печатал «typing…» вечно — бесконечный `sendChatAction` раз в 4 с, висящий статус-бабл и зелёный эмодзи у простаивающей сессии. С флагом: `idle`/`done` → статуса нет вовсе (отрабатывает обычный переход в idle), `working` → ярлык берётся с экрана, иначе из herdr, `blocked` → интерактивный промпт с экрана (клавиатуры AskUserQuestion/разрешений продолжают работать), иначе бабл «waiting for input», `unknown` или нет ответа → старый порядок. Соскоб экрана идёт в любом случае — им живут детект remote-control, vim-insert и пассивный shell-реле. На tmux флаг не меняет ничего.
- Парсер строки статуса (без флага, годится в апстрим) — строка со спиннером, содержащая маркер завершённого хода `· done`, больше не считается рабочим статусом: с Claude Code ≥ 2.1 это `<глиф> <Глагол> for <время> · done <время>` (плюс хвосты `· N shell(s) still running` / `· N background agent(s)`). Исключение — строка с `esc to interrupt`: прервать можно только живой ход. Найдя такую строку, сканер останавливается, а не идёт выше по скроллбэку, где старый спиннер воскресил бы ту же ошибку. Второй источник той же ошибки — баннер обновления `✔ Update installed · Restart to update`, который Claude вешает ровно на строку статуса и держит до перезапуска: галочка (U+2714) — это категория So, и эвристика `is_likely_spinner` принимала её за спиннер. Теперь семейство галочек и отмеченных чекбоксов (`✔ ✓ ✅ ☑ ☒`) исключено поимённо, а текст баннера ловится ещё и по словам — чтобы пережить и смену глифа, и смену формулировки.
- Посев session_map из нативного id сессии herdr (без флага) — `herdr agent list` публикует собственный id сессии Claude для каждой панели, ccgram выводит из пары (id, cwd) путь транскрипта `~/.claude/projects/<cwd с '/' → '-'>/<id>.jsonl` и, если файл есть, регистрирует сессию так же, как хуклесс-провайдеры. Лечит сессии, запущенные до установки хука (или с упавшим хуком): раньше у них был топик, но ни одной строки вывода. Чтение начинается с конца файла, история не проигрывается. Посев идёт при усыновлении топика и на каждом тике; когда сессия уже отслеживается, путь не трогает диск.

### Известное
- Сессии, запущенные до установки хука, теперь подхватываются посевом из нативного id herdr (см. патчи выше); в апстриме на tmux они остаются немониторимыми, потому что запись в session_map делает только событие SessionStart.
- Пара `CCGRAM_TOPIC_ON_DEMAND` + `CCGRAM_HERDR_REQUIRE_NATIVE_SESSION` работает вместе: без второго флага гонка двух идентичностей дала бы не два топика, а два предложения в General.
- Топики в приватном чате создаются только после того, как чат «замечен»: создай любой топик в чате с ботом и напиши в него.
