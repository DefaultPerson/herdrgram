# herdr — verified facts for herdrgram design (probed 2026-09-13 on the live machine)

## Environment
- Installed: herdr 0.7.1 (stable channel), protocol 14. Release notes cached for 0.9.0 (update available, not installed).
- Socket: `~/.config/herdr/herdr.sock` (default session). Named sessions: `~/.config/herdr/sessions/<name>/herdr.sock`.
- Persisted state: `~/.config/herdr/session.json` (workspaces/tabs/panes + `agent_session` per pane). Logs: `herdr-server.log`, `herdr-client.log`.
- Env injected into every pane process: `HERDR_ENV=1`, `HERDR_SOCKET_PATH`, `HERDR_WORKSPACE_ID`, `HERDR_TAB_ID`, `HERDR_PANE_ID`.
- The user's live layout: one workspace `wC`, one tab per Claude Code session (tabs wC:t1,t2,t3,t5,t7 → panes wC:p1,p2,p3,p5,p7), all running `claude --dangerously-skip-permissions`. Pane ids are `w<ws>:p<n>`, tab ids `w<ws>:t<n>`; numbers are reused after close (not durable). `terminal_id` (`term_...`) is unique per PTY.
- **DO NOT** send input to, close, or otherwise disturb panes wC:p1, wC:p2, wC:p3, wC:p5, wC:p7 (real user sessions). For live probing create a scratch tab: `herdr tab create --workspace wC --label herdrgram-probe-<x> --no-focus`, and close it afterwards with `herdr tab close <tab_id>`.

## Wire protocol (verified)
- Newline-delimited JSON over the unix socket. Request `{"id":"...","method":"...","params":{...}}`. Success `{"id":"...","result":{"type":"...", ...}}`. Error `{"id":"","error":{"code":"invalid_request"|"not_found"|..., "message":"..."}}` (note: error responses may carry an empty `id`).
- One request per connection works; `events.subscribe` keeps the connection open and streams one JSON object per line.

## Verified params / results
- `pane.get {pane_id}` → `{type:"pane_info", pane:{pane_id, terminal_id, workspace_id, tab_id, focused, cwd, foreground_cwd, agent:"claude", agent_status, agent_session:{source:"herdr:claude", agent:"claude", kind:"id", value:"<claude session uuid>"}, revision}}`. `agent_session` is omitted when unknown. **No transcript path is exposed** (the hook sends `agent_session_path` but the API does not return it); derive the JSONL path from cwd + session id the same way ccbot does (`~/.claude/projects/<encoded cwd>/<session_id>.jsonl`).
- `agent.list {}` → `{type:"agent_list", agents:[same shape as pane]}` — only panes with a detected agent. `pane.list {}` → all panes. `workspace.list` → `{workspaces:[{workspace_id,label,number,focused,active_tab_id,agent_status,pane_count,tab_count}]}`. `tab.list {workspace_id}` → tabs `{tab_id,workspace_id,label,number,focused,agent_status,pane_count}`.
- `tab.create {workspace_id, label?, cwd?, env?, focus:false}` → `{type:"tab_created", tab:{...}, root_pane:{pane_id,...}}`. `tab.close {tab_id}` → `{type:"ok"}`. `tab.rename {tab_id,label}`.
- `pane.send_input {pane_id, text}` → `{type:"ok"}` (multi-line text with `\n` accepted; typed literally). `pane.send_text {pane_id,text}` same idea. `pane.send_keys {pane_id, keys:["enter"]}` → ok. Key names: `enter`, `esc`, `ctrl+c`, `shift+tab`, `up`, `down`, `tab`, ... (herdr key-combo strings).
- `agent.send {target, text}` — target = pane id / terminal id / agent name; literal text, no Enter.
- `pane.read {pane_id, source:"visible"|"recent"|"recent-unwrapped"|"detection", lines?, format:"text"|"ansi"}` → `{type:"pane_read", read:{pane_id, workspace_id, tab_id, source, format, text, revision, truncated}}`. `detection` = the bottom-buffer snapshot the agent detector uses. `ansi` gives a colored snapshot (usable for screenshot rendering).
- `pane.wait_for_output {pane_id, source, match, regex?, timeout_ms?}` (needs `source`). `events.wait {match_event, ...}` (needs `match_event`). `agent.start {name, argv, cwd?, workspace_id?, tab_id?, split?, env?, focus?}` — CLI: `herdr agent start <name> [--cwd PATH] [--workspace ID] [--tab ID] [--split right|down] [--env K=V] [--focus|--no-focus] -- <argv...>`.
- `pane.process_info {pane_id}` → `{process_info:{shell_pid, foreground_process_group_id, foreground_processes:[{pid,name,argv,cmdline,cwd}]}}` — lets you confirm `claude` is actually running in the pane and with which flags.
- `notification.show {title, body?, sound?}` → shows a toast in the herdr UI (desktop side signal, e.g. "message from Telegram").
- `pane.report_metadata {pane_id, source, agent, title?, display_agent?, custom_status?, state_labels?, ttl_ms?, seq?}` — display-only pane metadata visible in the herdr sidebar (e.g. mark a pane as "📱 linked to Telegram topic X"). Text capped at 80 chars.
- `pane.rename {pane_id,label}` / `--clear`; `agent.rename`.
- `agent.explain {target}` → the detection rule evaluation. Claude Code rules include: `osc_title_working` (title starts with a spinner glyph), `live_turn_working`, `live_blocked_form` ("esc to cancel" after last horizontal rule → **blocked**; this is how AskUserQuestion / ExitPlanMode / permission prompts show up), `bash_permission_prompt`, `generic_permission_prompt` ("do you want to proceed?"), `mcp_elicitation_prompt`, `dynamic_workflow_prompt`, `live_prompt_box` (`❯` prompt → idle), `transcript_viewer`, `model_picker_menu`, `background_agents_working`, `background_mcp_task_working`, `btw_overlay_working`.

## events.subscribe (verified on 0.7.1)
- Params: `{"subscriptions":[{"type":"<event type>", ...scope}]}`. First line back: `{"id":..., "result":{"type":"subscription_started"}}`. Then events: `{"event":"<snake_name>","data":{"type":"<snake_name>", ...}}`.
- Accepted types on 0.7.1: `workspace.created, workspace.updated, workspace.renamed, workspace.closed, workspace.focused, worktree.created, worktree.opened, worktree.removed, tab.created, tab.closed, tab.focused, tab.renamed, pane.created, pane.closed, pane.focused, pane.moved, pane.exited, pane.agent_detected, pane.output_matched, pane.agent_status_changed`.
- Global (no scope needed): workspace.*, tab.*, pane.created, pane.closed, pane.exited, pane.focused, pane.moved, pane.agent_detected.
- **Per-pane only**: `pane.agent_status_changed` and `pane.output_matched` require `pane_id` (optionally `agent_status` filter). So a bridge must (re)subscribe per pane as panes appear (open a new subscription connection per pane, or one connection listing all known panes and reopen on change). Verify whether a stale pane_id in the list errors the whole subscription.
- **0.7.1 replays retained history on subscribe** (observed: subscribing replayed pane_created/tab_created/pane_agent_detected events for every existing pane). 0.9.0 changelog: "New lifecycle event subscriptions now start with live events rather than replaying retained history. API clients should subscribe before taking their initial snapshot." → the bridge must be idempotent w.r.t. replayed events and must reconcile from `pane.list`/`agent.list` on startup regardless of version.
- Observed payloads:
  - `{"event":"pane_created","data":{"type":"pane_created","pane":{pane_id,terminal_id,workspace_id,tab_id,focused,cwd,foreground_cwd,agent_status:"unknown",revision}}}`
  - `{"event":"pane_exited","data":{"type":"pane_exited","pane_id":"wC:p9","workspace_id":"wC"}}` (fires when the pane's process exits; tab auto-closes when its last pane exits)
  - `{"event":"pane_agent_detected","data":{"type":"pane_agent_detected","agent":"claude","pane_id":"wC:p1","workspace_id":"wC"}}` (also seen WITHOUT `agent` key = agent no longer detected / cleared)
  - `{"event":"tab_created","data":{"type":"tab_created","tab":{tab_id,workspace_id,label,number,focused,agent_status,pane_count}}}`
  - `{"event":"tab_renamed","data":{"type":"tab_renamed","label":"...","tab_id":"wC:t9","workspace_id":"wC"}}`
  - `pane.agent_status_changed` payload not yet captured (expected: pane_id, workspace_id, agent_status, maybe previous). Must be verified on a scratch pane running `claude`.
- `tab_closed` was NOT observed for a tab that closed because its only pane exited (only `pane_exited` arrived within the probe window) — treat `pane_exited` as the primary "session ended" signal and reconcile.

## Agent status semantics
`idle`, `working`, `blocked` (waiting for user: permission / AskUserQuestion / plan approval / MCP elicitation), `done` (finished and not yet viewed in the UI), `unknown`. Detection is screen-scrape + OSC title + the Claude SessionStart hook (`~/.claude/hooks/herdr-agent-state.sh`, integration version 7) which calls `pane.report_agent_session` with the Claude `session_id` (and `transcript_path`, which herdr stores but does not expose). The hook is the ONLY Claude hook currently configured in `~/.claude/settings.json` (SessionStart, matcher `*`). `herdr integration install claude` (re)installs it and overwrites the file; custom hooks must live beside it.

## Desktop-side affordances usable for UX
- `herdr agent focus <target>` / `workspace.focus` / `tab.focus` → jump the herdr UI to a pane (equivalent of ccbot `/show`, but no external terminal needed; herdr is already the terminal).
- `herdr --remote <ssh-target>` attaches to a remote herdr server over SSH (0.9.0 adds `herdr machine` for multiple saved machines) — laptop ↔ desktop continuity without the bot.
- `notification.show` toasts (config `[ui.toast] delivery = "terminal"` on this machine).
- `pane.report_metadata` title/display_agent/custom_status shown in the herdr sidebar.

## Claude Code facts relevant here
- Claude Code 2.1.270. Has built-in **Remote Control** (`claude --remote-control` / `/rc`, `claude remote-control` server mode, `remoteControlAtStartup` setting): bridges a local session to claude.ai/code and the Claude iOS/Android app, syncs both surfaces, forwards permission prompts and AskUserQuestion, supports images/files, push notifications. Limitations: claude.ai clients only (no Telegram / third-party API), requires claude.ai subscription login (not API key / setup-token / custom ANTHROPIC_BASE_URL), one remote session per interactive process, feature-flag env vars (`DISABLE_TELEMETRY`, `DO_NOT_TRACK`, ...) disable it. It is the official alternative to a Telegram bridge; herdrgram's differentiators are Telegram-native UX (forum topics, voice), multi-session overview across herdr, and zero dependence on claude.ai availability.
- Transcript JSONL: `~/.claude/projects/<cwd with / → ->/<session_id>.jsonl` (ccbot `session.py::_encode_cwd` / `_build_session_file_path`). `session_id` changes after `/clear`; `--resume` keeps writing to the original file. Claude Code hooks available for a bridge if desired: SessionStart, UserPromptSubmit, Stop, Notification (permission/idle), PreToolUse/PostToolUse, SessionEnd — could complement screen detection but herdr already covers status.

## Session state / restart semantics (from https://herdr.dev/docs/session-state/ and /docs/agents/, fetched 2026-09-13)
- Detach (`ctrl+b q`) keeps the server and all pane processes running; `herdr` reattaches. This is the tmux-attach equivalent — nothing to bridge.
- **herdr server restart kills pane processes** but restores workspaces/tabs/panes/cwd/layout/focus from `session.json`, and for panes with a stored `agent_session` it **automatically re-launches `claude --resume <session_id>`** ("After a client attaches and provides terminal size and theme context, Herdr resumes eligible restored agent panes across workspaces and tabs without waiting for each pane to be focused"). Requires claude integration version ≥ 6 (installed: 7). Panes without a session reference restore as plain shells.
  → After a herdr restart the Claude **session id stays the same** while `pane_id`/`terminal_id` are new. Binding recovery should therefore key on the Claude session id (plus cwd) and re-resolve the pane via `agent.list`. Caveat: the session id changes after `/clear` inside the same pane, so the binding must also track the live pane (terminal_id) and update its session id when `agent_session` changes (poll `pane.get` on `pane_agent_detected` / status change, or watch the JSONL directory).
- Scrollback survives restart only if `pane_history = true` in config (off by default; stored in `session-history.json`).
- Live handoff (`herdr update --handoff`) is experimental and keeps PTYs alive across server replacement.
- Claude Code detection authority is the **screen manifest** (TOML rules on the bottom-buffer snapshot + OSC title/progress); the claude integration has the "session" role only (native session identity for restore), it is NOT a lifecycle authority. So `blocked`/`idle`/`working` come from screen scraping — same fragility class as ccbot's terminal_parser, but maintained upstream (remote manifests auto-updated, `agent.explain` for debugging).
- `herdr agent rename <target> <name>` and `pane report-metadata --token summary=text` are the documented ways to attach custom labels visible in the sidebar.
