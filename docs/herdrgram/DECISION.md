# herdrgram — решение: строить с нуля или взять готовое

Дата: 2026-09-13. Статус: **рекомендация — adopt alexei-led/ccgram + маленький форк**. Окончательное решение за пользователем.

## Контекст
- Цель: ушёл от компа → продолжаю ту же сессию Claude Code в Telegram; вернулся → продолжаю в herdr; пишу с любой стороны. Без tmux.
- Исходная идея: переписать ccbot (tmux) под herdr в новом репо herdrgram.
- Разведка (docs/research/prior-art*.md) показала, что мост herdr ⇄ Telegram уже существует и активно развивается.

## Варианты

**A. Adopt ccgram как есть.**
- Плюсы: herdr-бэкенд верифицирован апстримом против ровно нашей версии 0.7.1 / protocol 14; автосоздание топиков для сессий, запущенных вручную в herdr (0 тапов, хук не обязателен); привязка топика переживает рестарт herdr (digest только из agent_session composite); блокирующие промпты с inline-кнопками; голос, скриншоты, live view, /send, worktree-топики, at-least-once доставка; 4364 теста (на этой машине прошли 7368 с параметризацией за 2 минуты); отзывчивый мейнтейнер.
- Минусы: закрытие топика в Telegram НЕ убивает панель (manually-discovered окна никогда не убиваются — гейт `view.origin == CCGRAM_CREATED_WINDOW_ORIGIN`); нет `/show`/`/focus` на десктоп; `/clear` в Claude ломает привязку (новый session id → новый топик); нельзя выключить эхо своих терминальных сообщений; мёртвый топик закрывается, а не удаляется; идентичность herdr-привязок в апстриме менялась дважды (риск ручной ре-привязки при апгрейде); открытые баги #245 (голодание живых топиков при реплее после рестарта) и #240 (probe удалённых топиков отключается навсегда после 3 сетевых ошибок); Python ≥3.14 (uv ставит сам).

**B. Adopt ccgram + маленький форк (рекомендуется).**
- Тот же ccgram, плюс 2 must-have патча (оценка агента ~150 строк суммарно, в местах, которые апстрим редко трогает):
  1. `CCGRAM_KILL_ON_TOPIC_CLOSE`: убивать herdr-панель при закрытии/удалении топика и для manually-discovered окон (снять гейт origin под флагом, вызвать `kill_window` из `topic_closed_handler`).
  2. `/show` (и кнопка в тулбаре): `guard_session_target` → `herdr agent focus <terminal_id>`; опционально `notification.show` «сообщение из Telegram» и `pane report-metadata --title` для пометки панелей, связанных с топиком.
- Nice-to-have патчи: флаг выключения эха своих сообщений (~10 строк); `delete_forum_topic` вместо `close_forum_topic` под флагом (1 строка); persistent blacklist для `/unbind` (~50-70 строк); `/usage` (~80-120 строк). `/clear`-ребиндинг — не чинить, вместо `/clear` открывать новую вкладку herdr.
- Патчи оформлять как PR в апстрим (мейнтейнер отзывчив), чтобы форк не расходился.

**C. Строить herdrgram с нуля (план Б).**
- Оправдано только если ccgram провалит недельный пробный прогон или если критичен полный контроль над моделью идентичности.
- Задел: docs/plan-b/ccbot-reuse-map.md (какие модули ccbot переиспользуемы и где сидит tmux) + проверенные факты API herdr 0.7.1 в docs/research/herdr-api-notes.md. Полный дизайн/план с нуля не дописаны — воркфлоу остановлен после пивота (см. docs/plan-b/README.md, как возобновить).
- Цена: месяцы на повторение Telegram-обвязки (рейт-лимиты, бэклог, delivery receipts, интерактивные UI, топики в приватных чатах), которую ccgram уже прошёл.

**D. Официальные альтернативы Anthropic — не закрывают сценарий.**
- Remote Control: та же сессия в claude.ai/приложении, но не Telegram, нужна подписка, 1 remote-сессия на процесс. Полезен как параллельный канал «на ходу», но не даёт обзора флота herdr-сессий.
- Channels Telegram-плагин: один бот = одна сессия, нет forum topics, нет голоса, есть permission relay. Для 5 параллельных табов неудобен.

## Рекомендуемая последовательность
1. Пробный прогон ванильного ccgram на живых herdr-сессиях по процедуре из docs/research/ccgram-fit-report.md (раздел «(c)»): отдельный тестовый бот или остановленный ccbot (иначе 409 на getUpdates), `AUTOCLOSE_*=0`, без `ccgram hook --install`, панель этой сессии спрятать через `herdr tab rename wC:t7 __main__`.
2. Неделя эксплуатации: понять, мешают ли реально отсутствие kill-on-close и `/show`.
3. Если да — форк `herdrgram` = fork ccgram с 2 патчами + PR в апстрим. Репо herdrgram тогда содержит форк (git remote upstream), а не переписанный ccbot.
4. План Б (с нуля) держим в docs/plan-b/ на случай провала.
